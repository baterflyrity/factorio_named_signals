# Named Signals

Мод для Factorio 2.1, который учит логические схемы различать, **от какого объекта пришёл сигнал**.

В ванили все объекты на одном проводе складываются в одну сумму: по ней не узнать, сколько железа в конкретном сундуке. Здесь объекту можно дать имя, и сравнивающий комбинатор берёт значение не только из всей сети, но и от одного источника или от группы источников с одинаковым именем. Провод при этом остаётся один.

## Что добавляет мод

### Именованные источники
Имя задаётся в панели **«Имя источника»** рядом с окном объекта. Панель видна, только если к объекту подключён провод логической сети. В режиме Alt имя видно над объектом.

| Объект | Что отдаёт как источник |
|---|---|
| Сундук (обычный и логистический) | содержимое |
| Конвейер | предметы на этом участке, только в режиме чтения «Непрерывно» |
| Резервуар | количество жидкости |
| Манипулятор | предмет в руке, только в режиме «Непрерывно» |
| Аккумулятор | заряд в % на сигнале, выбранном в аккумуляторе |

Одинаковое имя у нескольких объектов объединяет их в **группу**. Группу можно свернуть **агрегатом**:

| Агрегат | Значение для каждого сигнала |
|---|---|
| сумма | сумма по всем объектам группы |
| мин / макс | значение у самого пустого / самого полного объекта; пустой объект считается за 0 |
| средн. | среднее по всем объектам, с округлением вниз |
| кол-во | число объектов, в которых сигнал есть |

### Сравнивающий комбинатор с именами
Работает как ванильный сравнивающий комбинатор 2.0 и умеет больше:
- **Операнд**: источник («Вся сеть» или имя группы) + агрегат + сигнал + провода R/G. Для группы учитываются только объекты, подключённые к комбинатору проводом выбранного цвета; объект на обоих проводах считается один раз.
- **Условия**: сравнения `> < = ≥ ≤ ≠`, связки И/ИЛИ (И связывает сильнее). Справа — константа или второй операнд.
- **Спецсигналы**: «любой» и «все» слева; «каждый» слева и справа: схема считается по каждому сигналу отдельно.
- **Выход**: сигнал = 1 или значение со входа (из сети или от группы с агрегатом); «каждый» — прошедшие сигналы, «все» — весь состав источника выхода.
- **Окно**: текущее значение каждого операнда, при наведении — состав; выполненные условия подсвечиваются зелёным.
- Настройки сохраняются в чертежах и копируются через Shift+ПКМ / Shift+ЛКМ.

### ЛЭП-реле
Средняя опора ЛЭП со встроенным выключателем питания: питает зону 7×7, **только когда включена**.
- Не подключается к сети сама: медный провод на вход тянется вручную. Сокет один, как у обычной опоры.
- Управляется как выключатель питания: ручным тумблером или условием по сигналу. Провода логической сети подключаются к самой опоре.
- Питание дальше по цепочке не передаёт: управляемая сторона — только зона 7×7.
- Рецепт — средняя опора + выключатель питания; открывается вместе со средней опорой.

Ограничения: конвейеры и манипуляторы читаются только в режиме «Непрерывно»; «любой» и «все» справа и «любой» на выходе не поддерживаются.

## Примеры схем

Запись: `Склад[мин]: железо < 100 → A=1` — «если у группы *Склад*, свёрнутой агрегатом *мин*, железа меньше 100, выдать сигнал A = 1». Без имени — вся сеть. `каждый`, `любой`, `все` — спецсигналы. Во всех примерах источники могут висеть на одном проводе вместе с чем угодно ещё.

### Склады и буферы
1. **Самый пустой сундук.** `Буфер[мин]: железо < 100 → A=1` — пополнить буфер, как только опустел хоть один сундук, а не их сумма.
2. **Переполнение одного сундука.** `Буфер[макс]: железо > 4000 → стоп=1` — остановить загрузку, пока один из сундуков не забит.
3. **Неравномерность группы.** `Буфер[макс]: железо > 3000` И `Буфер[мин]: железо < 500 → A=1` — включить перекладчик между сундуками.
4. **Сколько сундуков пусто.** `Буфер[кол-во]: железо < 8 → A=1` — в группе из 8 сундуков хотя бы один без железа.
5. **Склад пуст.** `все @ Склад < 1 → A=1` — пусто всё, сигнал тревоги.
6. **Посторонний предмет.** `любой @ Мусор > 0 → A=1` — в сундук отходов что-то попало, запустить очистку.
7. **Чего не хватает до запроса.** `каждый @ Запрос > каждый @ Склад → каждый (значение из Запрос)` — список недостающих предметов, например для запроса поезда.
8. **Балансировка двух складов.** `каждый @ А < каждый @ Б → каждый=1` — какие предметы перекладывать из Б в А.
9. **Средняя заполненность.** `Буфер[средн.]: медь ≥ 0 → медь (значение из Буфер[средн.])` — условие истинно всегда, на выходе среднее по сундукам: индикатор без арифметических комбинаторов.

### Производство
10. **Вход есть, выход забит.** `Вход: руда > 0` И `Выход: пластины > 1000 → стоп=1` — входной и выходной сундуки одной линии на одном проводе.
11. **Приоритет продукции.** `Склад: шестерни > 500` И `Склад: трубы < 200 → трубы=1` — делать трубы только при запасе шестерён.
12. **Держать пропорцию.** `Склад: зелёные схемы < Склад: шестерни → A=1` — включить сборщик схем, если они отстают от шестерён.
13. **Готов ли набор для крафта.** `все @ Ингредиенты ≥ 50 → старт=1` — каждого ингредиента в сундуке не меньше 50. «Все» видит только то, что есть в сундуке: если ингредиент может закончиться совсем, добавьте для него условие `И Ингредиенты: X > 0`.
14. **Остановить лишнее.** `каждый @ Склад > 2000 → каждый=1` — сигналы «хватит» по предметам, которых уже достаточно.
15. **Контроль одной линии в общей сети.** `ЛинияАссемблеров: пластины < 20 → A=1` — сундук-буфер одной линии среди десятка других на том же проводе.

### Конвейеры и манипуляторы
16. **Лента дошла.** `Лента: железо > 0` И `Склад: железо < 100 → A=1` — подача идёт, но склад ещё не наполнился.
17. **Лента занята по всей длине.** `Лента[кол-во]: железо = 6 → A=1` — железо есть на всех шести именованных участках (признак затора перед потребителем).
18. **Пустая лента перед печами.** `Подача[мин]: уголь < 1 → тревога=1` — хотя бы один участок без угля.
19. **Что несёт манипулятор.** `любой @ Рука > 0 → все (значение из Рука)` — вывести предмет в руке на лампу или табло.
20. **Не перегрузить назначение.** `Рука: железо > 0` И `Назначение: железо > 1000 → стоп=1` — манипулятор несёт железо туда, где его уже много.

### Жидкости
21. **Крекинг по уровню.** `Тяжёлая[сумма]: тяжёлая нефть > 20000 → крекинг=1` — резервуары тяжёлой нефти на одном проводе с остальными.
22. **Баланс нефтепродуктов.** `Лёгкая: лёгкая нефть > Газ: газ → крекинг=1` — сравнение двух резервуаров напрямую.
23. **Водяной буфер.** `Вода[мин]: вода < 5000 → насосы=1` — включить насосы, если опустел хоть один резервуар.

### Энергия и ЛЭП-реле
24. **Сброс нагрузки.** `Аккум[средн.]: A < 20 → стоп=1` — сигнал на ЛЭП-реле второстепенной зоны: выключить её при низком заряде.
25. **Резервная станция.** `Аккум[мин]: A < 30 → старт=1` — включить подачу топлива в резервные котлы.
26. **Отключение блока по складу.** `Продукция: схемы > 5000 → стоп=1` — ЛЭП-реле обесточивает сборочный блок, когда склад полон.
27. **Ручной рубильник.** ЛЭП-реле без условия, ручной тумблер — обесточить зону для перестройки, не разрывая провода.
28. **Свет по требованию.** Условие у реле — сигнал от датчика (например, игрок на станции); реле питает только лампы своей зоны.

### Удобство и отладка
29. **Один провод вместо многих.** Все сундуки, ленты и резервуары цеха — на одном зелёном проводе, а условия различают их по именам: проводка в разы проще.
30. **Отладка без ламп.** Открыть комбинатор и навести на значение операнда — виден состав сети или группы с иконками, без лишних ламп и дисплеев.

## Структура репозитория

```
named-signals/      мод (info.json, control/data, scripts/, prototypes/, locale/, changelog.txt)
tests/              проверки без запуска игры: Lua через lupa на имитации API
tools/build.py      сборка zip и установка в папку mods
CHANGELOG.md        история изменений по версиям
```

| Модуль | Отвечает за |
|---|---|
| `scripts/logic.lua` | движок условий — чистая функция от карт сигналов, без обращений к игре |
| `scripts/signals.lua` | ключи сигналов, агрегаты, rich text |
| `scripts/sources.lua` | реестр имён, чтение вклада каждого объекта, подписи |
| `scripts/combinator.lua` | составная сущность комбинатора, топология сетей, контекст для движка |
| `scripts/relay.lua` | составная сущность ЛЭП-реле, перенос проводов, миграция |
| `scripts/gui.lua` | окна комбинатора, справки и панель имени |
| `control.lua` | только регистрация событий |

## Разработка

```bash
pip install lupa
python tests/run_all.py                                     # все проверки
python tools/build.py                                       # dist/named-signals_<версия>.zip
python tools/build.py --install "%APPDATA%\Factorio\mods"   # собрать и установить
```

Для сетевой игры у всех игроков должна быть одна и та же версия мода.
